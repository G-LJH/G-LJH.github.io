背景与问题

临床侧高频咨询高度重复，却仍要医生亲自回；口径不一致还会带来体验与合规风险。真正的难点不只是「能回答」，而是：能不能进真实患者入口，以及答错时有没有边界。

交付约束 要上企业微信患者端，而不是只做可演示的网页聊天。
项目结果 8 位专科智能体交付；模板复用后后续搭建周期缩短约 80%。

三个关键判断

01 · 工作流

先还原医生工作，再配 Agent

不问「能接哪些模型」，先问高频意图、异常分支与医生真正想省下的时间。

02 · 安全

边界优先于话术炫技

意图兜底、安全过滤与确定性回复优先，降低幻觉、越界和非标准回复风险。

03 · 复制

做矩阵 + 模板，不做 8 个孤岛

专科知识库与策略可定制，但搭建路径标准化，为 1-N 复制留口。

我怎么做

  • 场景拆解：科室调研，把问答、挂号指引、购药引导拆成可执行意图与流程。
  • Agent 设计：基于 FastGPT 搭建 8 位专科智能体，配置知识库、Prompt / 对话策略与多分支工作流。
  • 接入交付：打通企业微信患者端，进入真实咨询链路；处理 Markdown 等渲染兼容问题。
  • 资产沉淀：抽象专家智能体模板，把后续搭建从「重做一遍」变成「填差异」。

结果

  • 交付 8 位专科医生智能体，并接入企业微信患者端
  • 沉淀标准化模板，后续搭建周期缩短约 80%
  • 回答可引用知识库依据，降低「凭空发挥」的观感与风险
