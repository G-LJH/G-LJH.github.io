给内部办公用的个人 Agent 底座

公司和联想合作，要给内部员工提高办公效率。先内部试用，体验过关再考虑外推。按一层底座来做：现在已经能对着项目文件夹干活、留下长期记忆、开会转写、定时执行——不是又一个通用聊天框。

为什么做

第一版就要能真用，不能只是 Demo

这是公司与联想合作的内部效率项目：内部测下来如果体验好，后续有机会往外推。因此我没有从功能清单出发，而是先做了下面三条产品取舍。

01

做专用，不做人设上的通用

通用办公助手拼入口和「什么都能聊」。内部员工真正卡住的是对着项目、文件、会议把事做完。第一版先把「选定文件夹就能干活」做透。

02

先做成底座，再往上加能力

会议、记忆、定时任务不做成彼此孤立的工具，而是接到同一个 Agent：默认在项目里聊，需要现场就开会，重复的事交给定时任务。

03

必须有长期记忆

模型会越来越像。真正能越用越深的，是这个项目上次定过什么、材料堆在哪、会上答应过什么——这些还在。记忆不是附赠。

我做成了什么

底座上已经接上的四件

它干活时看的是当前文件夹、工作区材料、本地记忆和会议记录。新能力按同一套底座往上接。

01 · 碰得到项目

项目工作台

选定本地项目文件夹，Agent 直接读文件、改内容、跑命令。不是把文件贴进对话框，是对着本地目录干活。

02 · 能攒下来

长期记忆

把还要用的决策和材料写成本地文档，下次还能找回来。护城河不在模型，在还在的上下文。

03 · 现场进得来

AI 会议

录音 / 录屏 / 转写，会后摘要和行动项进当前项目。开会不是另开一个录音软件。

04 · 能主动跑

定时任务

到点执行，结果回到同一条对话。重复事项按计划跑，不必每次重新发起。

实现取舍

做成可运行版本时的边界

01

数据先放本机

这版没有云端账号。代码、记忆与会议录音留在本机，用户能够检查。

02

记忆只记以后还值钱的

不把每句闲聊存下来；只沉淀以后还要用、且不容易重新推导的信息。

03

Web、桌面、命令行是同一个 Agent

入口可以不同，底座是一套；新能力往同一个 Agent 上接，而不是另起一个。

我的角色

参与定位与取舍，并用 AI 编程接到可运行版本

我参与产品定位和「专用 / 底座 / 记忆」三条取舍，并用 AI 编程把工作台、记忆、会议、定时任务接到可运行版本。

  • 产品取舍：不做万金油通用助手，先做成可扩展的专用底座。
  • 能力落地：把四件能力接到同一条工作体验，而不是四个孤立插件。
  • 实现边界：底层 Agent 能力基于 pi 做集成和扩展，不是从零写一套模型运行时。
