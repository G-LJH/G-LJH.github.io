企业微信会话存档

合规与质检需要会话数据，但官方存档贵、对接重。用 xbotox 回调完成捕获与入库，把合规成本从约 9 万/人/年 降到接近 0，并做成可部署的服务能力。

合规降本 数据链路 可部署交付 开源可跑
查看 GitHub 全部作品

背景与问题

会话存档是合规审计与服务质量的基础能力。官方路径费用高、对接复杂，中小团队很难负担；即便存下来，还要能进内部系统，而不是锁死在厂商黑盒里。

成本锚点 官方会话存档约 9 万/人/年——这是方案成立的第一性条件。
交付标准 能稳定收、能结构化存、能运维上线，而不是一次性脚本。

三个关键判断

01 · 路径

用回调换成本结构

不跟官方接口硬刚全量能力，先打通「捕获 → 解析 → MySQL」这条可负担主链路。

02 · 交付

部署必须可复制

轻量服务 + 日志与健康检查，方便进入公司/客户环境，而不是只在自己电脑能跑。

03 · 延展

为后续智能应用留口

结构化存储文本/图片/文件消息，预留质检与 RAG 使用，而不是存完即死。

我怎么做

  • 链路设计：企微消息经 xbotox 捕获后回调到自建服务，解析并写入 MySQL。
  • 工程落地：Flask 服务、去重、日志；支持单聊/群聊与常见消息类型。
  • 可运维：容器化部署到 1Panel 等环境，保证可持续跑而不是演示一次。
  • 产品化：推动成为可对外说明的服务能力——重点是降本与可交付，而不只是个人练习。

结果

  • 合规成本：约 9 万/人/年 → 接近 0（相对官方存档路径）
  • 形成可开源、可部署的回调存档服务
  • 数据落库后可进入后续质检 / 知识应用，而不是一次性导出

证据

技术栈

  • Python · Flask · MySQL · Webhook · 企业微信 / xbotox

开源仓库：xbotox-callback-storage（站内路径名 wecom-archive）。配置与建表细节见仓库；本页强调成本判断与交付结果。
