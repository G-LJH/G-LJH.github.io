# agent-for-you 作品页设计说明

## 目标

将现有偏“功能说明书”的详情页改造成面向 AI 产品经理岗位的精简案例页。HR 应在 2–3 分钟内理解：产品解决什么问题、核心功能如何构成完整闭环、关键产品取舍是什么，以及候选人如何借助 Vibe Coding 将方案落成可运行 Demo。

## 核心叙事

主命题为：**工作不发生在聊天框，而发生在项目和时间里。**

agent-for-you 不是另一个聊天界面，而是尝试把一次性 AI 对话变成能围绕真实项目持续工作的本地个人 Agent。页面围绕三个问题组织：

1. 会话结束后，Agent 如何保留真正有长期价值的上下文？
2. 文件、会议与重复任务分散在不同工具里，Agent 如何接入完整工作流？
3. 涉及代码、文件和会议内容时，如何建立本地优先、可检查的信任边界？

## 页面结构

1. 首屏：产品定位、个人独立项目身份、AI 产品经理角色、Vibe Coding 落地方式、GitHub 入口。
2. 产品问题：用三个短卡片说明“上下文会断、工具彼此割裂、Agent 只能被动响应”。
3. 产品判断：用一句核心判断串起“项目上下文—长期记忆—主动触发”。
4. 核心功能：2×2 卡片介绍项目工作台、工作区与长期记忆、AI 会议、定时任务。每张卡同时说明功能、对应问题和用户价值。
5. 关键产品决策：本地优先、记忆重质量而非数量、同一 Agent 多入口复用。
6. 我的贡献：如实说明独立完成产品定义、功能规划、交互设计与 Demo 迭代；通过 Vibe Coding 推进实现；底层 Agent 基于 pi 集成。
7. 结尾：引导查看 GitHub 仓库。

## 图片策略

- 使用源码仓库中的 2940×1440 原始截图替换 1024×686 压缩图。
- 核心功能截图使用两列小卡片呈现，避免整张图片铺满内容区。
- 图片固定视觉比例并从顶部裁切；点击后打开原图，兼顾浏览速度和细节查看。
- 移动端改为单列，但保持图片高度受控。
- 会议使用 1505×1045 的录音工作台原型图，展示实时转写、摘要、待办和本地录音状态。

## 文案边界

- 不表述为“从零手写全部代码”。
- 使用“独立完成产品定义、交互设计与 Demo 迭代，通过 Vibe Coding 推进实现”。
- 明确“底层 Agent 能力基于 pi 集成与扩展”。
- 技术细节服务于产品判断，不将页面写成架构文档。

## 验收标准

- 页面包含“AI 产品经理”“Vibe Coding”“基于 pi”等真实职责信息。
- 页面明确展示四项能力：项目工作台、工作区与长期记忆、AI 会议、定时任务。
- 页面包含至少三个关键产品决策，而非只罗列功能。
- 四张功能截图均有替代文本、可打开原图，且图片文件实际存在。
- 项目工作台、工作区和定时任务截图宽度至少 2500px；会议图宽度至少 1400px。
- 作品列表摘要与详情页新定位一致。
- 桌面端两列展示功能卡片，手机端单列展示，无横向溢出。
