# AI Agent Builder 首页介绍设计

## 目标

将个人官网首页从偏产品或单一 FDE 的表达，统一为「AI Agent Builder｜产品理解 × 工程落地」。让产品与技术招聘方都能快速理解：刘佳慧能够贯通业务、产品、工程、评测与交付，并希望逐步独立负责 AI Agent 的完整链路。

## 定位原则

- 当前身份使用 `AI Agent Builder`，不限定为产品经理、AI Agent 工程师或 FDE。
- 「产品理解 × 工程落地」是定位的核心解释，不是两个互相竞争的求职方向。
- 技术表述必须对应已有项目证据；不使用「精通」「生产级专家」等超出当前经历的措辞。
- 职业规划只保留一句，说明发展方向和责任边界，不展开阶段、行业清单或 T 型人才定义。

## 首页文案设计

### 首屏

- Eyebrow：`Hangzhou · AI Agent Builder`
- 主定位：`AI Agent Builder｜产品理解 × 工程落地`
- 简介：`站在业务、产品与工程之间，把真实问题做成可运行、可评测、可交付的 AI Agent。`
- 保留教育信息、GitHub、作品和两份定向简历入口。

### 能力与方法

四张能力卡共同覆盖完整链路：

1. **需求与产品定义**：业务调研、工作流还原、需求价值判断、场景与异常分支拆解。
2. **Agent 工程实现**：工作流、RAG / 知识库、Prompt、Tool Use、Context / Memory、API 接入与可运行原型。
3. **评测与效果迭代**：Testcase、评测集、Bad Case 归因、LLM-as-a-Judge、回归验证和调优。
4. **部署交付与复制**：Docker / 1Panel、渠道集成、上线验收、SOP / Skill 沉淀和 1-N 复制。

卡片表达采用「解决什么问题 + 如何完成」的句式。技术名词放在证据行，避免正文变成工具清单。

### 自我介绍

将现有偏产品的自我评价改为一段 Builder 表述：既能理解业务、做产品取舍，也能借助代码和 AI 工具完成 Agent 原型、系统接入、评测优化与交付验证。强调全链路实践，但不声称已经独立承担过中大型项目。

### 职业规划

新增一条紧凑表述：

> 成为贯通业务、产品、工程与交付的全链路 AI Agent Builder，独立负责从需求判断到上线迭代的完整闭环，并对最终业务结果负责。

职业规划紧邻自我介绍呈现，不新增长篇时间线。

## 实现范围

- 修改 `index.html` 中的页面描述、首屏、能力卡、自我介绍和职业规划。
- 仅在现有布局不足以容纳新增职业规划时，对 `css/home-capabilities.css` 做最小样式调整。
- 更新与首页文案直接相关的测试断言。
- 不修改简历 PDF、项目详情页、作品 PDF、实习事实和量化数据。

## 验收标准

- 首屏在一个视区内清楚出现 `AI Agent Builder` 与 `产品理解 × 工程落地`。
- 页面不再把个人定位限制为 FDE，也不把产品与工程写成互斥方向。
- 能力区同时具备产品判断、Agent 工程、评测和部署交付证据。
- 职业规划只有一句，能明确表达「独立负责完整链路并对结果负责」。
- 所有本地链接有效，桌面端与移动端无新增溢出或布局破坏。
- 现有首页测试及相关回归测试通过。
