# 首页“能力与自我评价”模块设计

日期：2026-08-14

## 目标

在个人站首页增加“能力与方法”模块，服务 AI 产品经理与 AI Agent 工程师两类求职方向，突出“产品、技术、交付三端闭环”的复合定位。

新模块不重复罗列实习经历或技术栈，而是先归纳解决问题的方法，再由后续经历和作品提供证据。招聘方应能在快速浏览时理解候选人的四类核心能力，并记住其复合型职业定位。

## 页面位置与信息层级

首页顺序调整为：

1. 个人定位（Hero）
2. 能力与方法
3. 实习经历
4. 作品
5. 联系

导航栏增加“能力”锚点，指向新模块。新模块位于 Hero 与实习经历之间，作为阅读后续案例的判断框架。

模块内部顺序为：

1. 标题“能力与方法”
2. 引导语“不是工具清单，而是我解决问题的四种方式。”
3. 四张能力卡片
4. 一条深色自我评价卡片

## 能力卡片内容

### 场景与产品

澄清客户需求，拆解业务场景与流程，识别 AI 能力边界，把模糊问题转成可实现、可验收的产品方案。

关键词：需求调研 · 流程建模 · 方案设计 · 验收推进

### Agent 构建

设计 Agent 工作流、知识体系、SOP 与 Prompt，并补齐工具调用、多轮对话、异常兜底和转人工策略。

关键词：FastGPT · RAG · Knowledge · Tool Use

### 评测与优化

通过 Testcase、评测集和 Bad Case 归因定位问题，持续优化 Prompt、知识与配置。

代表证据：约 600 条评测集通过率 85% → 92%

### 交付与复用

推动方案完成上线、培训、复盘与规模化复制，并将一次性经验沉淀为模板、SOP 和 Skill。

代表证据：1 个月交付 19 个 Agent · 37 个意图骨架

## 自我评价

使用以下两句话收束复合定位：

> 我擅长在业务场景、AI 能力边界、产品方案与研发实现之间做连接，推动 Agent 从需求走到上线，再沉淀成可复用的方法。比起只做需求翻译，我更愿意自己下场搭建、评测和造工具，把模糊想法变成真正可用的结果。

## 视觉与响应式设计

- 复用现有首页的 `block-section`、`section-label`、`tile` 和配色体系，不引入新的视觉语言。
- 桌面端四张能力卡使用两列网格，便于快速比较与扫描。
- 移动端改为单列，保持卡片正文和代表证据的自然阅读顺序。
- 卡片内部依次展示能力名称、能力说明、关键词或代表证据。
- 自我评价使用横跨整行的深色卡片，与浅色能力卡形成层级差异，并延续现有详情页深色结果区的风格。
- 新模块沿用现有页面间距、圆角、边框和阴影变量。

## 交互与可访问性

- 导航栏“能力”链接使用页内锚点，不新增 JavaScript。
- 新模块使用语义化 `section`、标题和 `article` 结构。
- 文字颜色需满足现有站点的可读性标准；关键词不能只依赖颜色表达含义。
- 响应式布局不改变内容顺序，键盘和屏幕阅读器读取顺序与视觉顺序一致。

## 实现边界

- 仅修改首页结构与公共样式；不修改作品详情页、简历 PDF 或现有项目内容。
- 不增加图标库、动画框架、外部依赖或新的 JavaScript 交互。
- 不把完整工具栈搬到首页；工具名称只作为能力卡的辅助信息。
- 不新增独立“自我评价”导航项，自我评价作为“能力与方法”的收束内容。

## 验证标准

- 导航栏可正确跳转到“能力与方法”模块。
- 桌面端显示两列能力卡，移动端显示单列卡片，无溢出或文字遮挡。
- 四张能力卡和自我评价文案完整、顺序正确。
- 现有 Hero、实习经历、作品、联系和简历下载交互不受影响。
- 页面继续通过现有自动化测试，并补充针对新模块内容和锚点的断言。
