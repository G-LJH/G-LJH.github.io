# 首页 Agent 交付故事改版设计

## 目标

把首页斑头雁经历下的“美妆集团多店交付”和“时尚鞋服集团效果优化”改写为两个可在十几秒内读完的独立项目故事。两个项目分别体现规模化上线和效果优化能力，共同证明产品判断、Agent 工程实践和 FDE 交付能力，并能作为面试口述的提纲。

## 事实边界

- 两组成果来自两个不同的头部零售客户，必须保留为两个独立项目故事。
- 客户继续匿名，不增加未经现有履历证实的业务细节。
- 保留现有可验证数据：近一个月交付并上线 19 个智能体、37 个意图骨架、每周约 400 条真实对话 Bad Case、约 600 条评测集、通过率由 85% 提升至 92%、方法沉淀为团队复用的 Skill。

## 页面结构

在当前公司经历卡片中保留 “Agent for You” 项目，并将后面两个客户项目分别改为以下结构。

### 故事一：多店规模化交付

1. **标题**：`某头部美妆集团 · 多店规模化交付`
2. **故事钩子**：`19 个 Agent，不能靠重复交付 19 次。`
3. **痛点**：多品牌、多店铺需要重复整理客户资料、商品知识、活动规则和 FAQ，并逐店重做 SOP，交付成本随店铺数量增长。
4. **解决**：拆出 37 个意图骨架，建立“情景骨架—证据提取—SOP 合成—Excel 审阅—正式定稿”的迁移流程，并沉淀为团队复用的 Skill。
5. **成果**：近一个月完成 19 个智能体优化交付并全部上线。
6. **总结**：`我把逐店重复搭建，变成了一套可复制的规模化交付方法。`

### 故事二：真实 Bad Case 驱动的效果优化

1. **标题**：`某时尚鞋服集团 · Agent 效果优化`
2. **故事钩子**：`400 条 Bad Case，不能都靠修改 Prompt 解决。`
3. **痛点**：真实对话中的效果问题来源不同，如果统一归因于模型或 Prompt，只会反复修改而无法定位根因。
4. **解决**：每周独立分析约 400 条真实对话，区分 Prompt、知识缺失、业务规则不清、配置错误和平台能力问题；针对不同根因分别处理，并将平台层问题转化为产品需求。
5. **成果**：约四周内协助将约 600 条评测集的人工评测通过率由 85% 提升至 92%。
6. **总结**：`我把凭感觉调优，变成了基于归因和评测的优化闭环。`

两个项目都采用“故事钩子—痛点—解决—成果—总结”的一致结构，但不共享同一冲突或结论。痛点、解决和成果使用简短标签帮助扫读；总结使用视觉上稍强调但不喧宾夺主的样式。正文保持短段落，不展开成长篇案例复盘。

## 视觉与响应式

- 延续现有卡片、字体、颜色和间距体系，不引入新的视觉主题或交互。
- 标签与段落在桌面端保持紧凑，在窄屏自然换行。
- 不添加动画、折叠或弹窗；故事本身承担表达，不依赖装饰制造“故事感”。

## 验证

- 更新首页测试，确认两个客户项目仍分别存在且顺序不变。
- 确认两个故事各自的钩子、痛点/解决/成果标签、总结及对应关键数字存在。
- 确认 19 个智能体与 37 个意图骨架只出现在美妆集团故事中，400 条 Bad Case、600 条评测集和 85% 至 92% 只出现在鞋服集团故事中。
- 运行现有首页测试，确保作品、能力和其他经历未受影响。
- 本地渲染桌面与移动宽度，检查段落密度、换行和层级。

## 不在本次范围

- 不合并两个客户项目，也不重写其他代表项目。
- 不修改作品详情页、简历 PDF 或作品集 PDF。
- 不新增客户名称、Logo、截图或其他可能涉及保密边界的素材。
