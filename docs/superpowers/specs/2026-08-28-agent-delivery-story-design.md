# 首页 Agent 交付故事改版设计

## 目标

把首页斑头雁经历下分开的“美妆集团多店交付”和“时尚鞋服集团效果优化”两个条目，整合成一个可在十几秒内读完的代表项目故事。故事需要同时体现产品判断、Agent 工程实践和 FDE 交付能力，并能作为面试口述的提纲。

## 事实边界

- 两组成果来自两个不同的头部零售客户，页面不能暗示它们属于同一个客户或同一个项目。
- 客户继续匿名，不增加未经现有履历证实的业务细节。
- 保留现有可验证数据：近一个月交付并上线 19 个智能体、37 个意图骨架、每周约 400 条真实对话 Bad Case、约 600 条评测集、通过率由 85% 提升至 92%、方法沉淀为团队复用的 Skill。

## 页面结构

在当前公司经历卡片中保留 “Agent for You” 项目，将后面两个客户项目替换为一个项目块：

1. **标题**：`头部零售客户 · Agent 规模化交付`
2. **故事钩子**：`19 个 Agent，不能靠重复交付 19 次。`
3. **痛点**：多品牌、多店铺需要重复整理资料和编写 SOP；上线后的 Bad Case 缺少统一归因，交付陷入重复劳动和反复救火。
4. **解决**：拆出 37 个意图骨架，建立“证据提取—SOP 合成—人工审阅”的迁移流程；按 Prompt、知识、规则、配置和平台问题归因真实 Bad Case，并用评测集验证优化结果。
5. **成果**：近一个月完成 19 个智能体交付并全部上线，约 600 条评测集通过率由 85% 提升至 92%，方法沉淀为团队复用的 Skill。
6. **总结**：`我解决的不只是某个 Agent 的问题，而是把一次性交付变成了可复制、可评测的交付方法。`

痛点、解决和成果使用简短标签帮助扫读；总结使用视觉上稍强调但不喧宾夺主的样式。正文保持短段落，不展开成长篇案例复盘。

## 视觉与响应式

- 延续现有卡片、字体、颜色和间距体系，不引入新的视觉主题或交互。
- 标签与段落在桌面端保持紧凑，在窄屏自然换行。
- 不添加动画、折叠或弹窗；故事本身承担表达，不依赖装饰制造“故事感”。

## 验证

- 更新首页测试，确认两个旧客户项目标题不再作为独立项目块出现。
- 确认新标题、故事钩子、痛点/解决/成果标签及关键数字存在。
- 运行现有首页测试，确保作品、能力和其他经历未受影响。
- 本地渲染桌面与移动宽度，检查段落密度、换行和层级。

## 不在本次范围

- 不重写其他代表项目。
- 不修改作品详情页、简历 PDF 或作品集 PDF。
- 不新增客户名称、Logo、截图或其他可能涉及保密边界的素材。
